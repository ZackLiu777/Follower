# beta.md

## Beta 版本目标

Beta 版本的目标不是扩大平台覆盖，而是在 **iOS 单平台** 上把产品从“可用的工程原型”推进到“完成度显著更高的成熟产品”。本阶段的重点不是再增加架构层级，而是在既有 **GRDB + SQLite / MVVM / Repository / Service / Feature-first** 基础上，提升语言、本地化、主题、视觉细节、交互反馈、状态表达与整体一致性。

Beta 的判断标准不是“是否还能运行”，而是：用户是否能在 iPhone 上感受到这是一个经过完整打磨的 iOS 产品，而不是模板项目的延续。

---

## 1. Beta 的设计约束

1. 仅面向 iOS，不追求 iPadOS、macOS、watchOS、visionOS 的适配。
2. 不改变当前分层边界，不引入新的数据访问范式，不回退到 SwiftData。
3. 所有新增能力必须服从现有架构：View → ViewModel → Service → Repository → Database。
4. 视觉和交互优化优先于功能膨胀。
5. Beta 阶段的目标是“完成度”，不是“覆盖率”。

---

## 2. Beta 的核心工作流

Beta 阶段的主要工作分为三条主线：

* 多语言本地化：原生 English 之外，补齐 简体中文 / 繁体中文 / 日文。
* 主题系统升级：在现有 Apple Native / Instagram / Liquid Glass 基础上继续细化，建立可切换、可扩展、可一致渲染的主题体系。
* iOS 体验精修：优化页面结构、动效、层次、文案密度、状态反馈、空状态、错误状态和过渡状态。

这三条主线彼此独立，但都只允许作用在表现层和配置层，不能污染数据层与业务层。

---

## 3. 多语言支持

### 3.1 目标

当前原生语言为 English。Beta 阶段需要补齐：

* 简体中文（zh-Hans）
* 繁体中文（zh-Hant）
* 日文（ja）

多语言不是简单翻译字符串，而是完整的本地化系统：

* 文案本地化
* 数字格式本地化
* 日期格式本地化
* 单位表达本地化
* 复数形式与句式本地化
* 图表与空状态文本本地化

### 3.2 实现原则

* 所有 UI 文本必须通过统一的 localization key 访问。
* 不允许在 View 中散落硬编码字符串。
* Settings 页必须提供语言切换入口。
* 语言选择应具备持久化能力，重启后仍然生效。
* 语言切换必须是 UI 层行为，不应渗入 Repository 或 Service。

### 3.3 文案策略

Beta 阶段的文案策略应遵循：

* 英文作为语义基准。
* 中文文案偏短，避免过度书面化。
* 日文文案保持自然、简洁、界面友好。
* 不同语言下的按钮文案应按可用空间调整，不要求逐字对齐。

### 3.4 本地化范围

必须覆盖：

* Dashboard
* Trends
* Settings
* Account
* Upgrade Prompt
* Premium Gate
* Empty State
* Error State
* Loading State
* Export Flow
* Permission / Privacy 文案

---

## 4. 主题系统升级

### 4.1 目标

当前已有：

* Apple Native 主题
* Instagram 主题
* Liquid Glass 卡片效果

Beta 阶段不是简单增加几个颜色值，而是把主题系统从“配色切换”推进为“界面语义切换”。也就是说，主题需要影响：

* 背景
* 卡片层
* 分割线
* 主色与强调色
* 图表线条与渐变
* 按钮状态
* 导航区层级
* 空状态插画/图形风格
* Premium 门控视觉

### 4.2 Instagram 风格的进一步收敛

Instagram 风格不只是粉橙渐变，而是一个明确的视觉语义集合：

* 高饱和强调色
* 柔和但明显的渐变过渡
* 轻量毛玻璃卡片
* 有节奏的圆角层次
* 更偏社交产品的视觉温度
* 图表曲线和统计卡片具有更高的视觉动势

### 4.3 主题扩展方向

Beta 阶段可以继续增加但不强制增加的主题风格包括：

* Midnight / Dark Pro：偏深色、高对比、低噪声
* Soft Pastel：低饱和、轻盈、偏内容型
* Neon Accent：用于更强的视觉强调，但只能作为可选项

这些主题的目标不是“看起来花”，而是为不同使用情境提供明确视觉语义。

### 4.4 主题实现约束

* 主题配置统一通过 EnvironmentValues 注入。
* View 不应直接写死颜色常量。
* 图表、卡片、按钮、Badge、Empty State 都必须读取主题上下文。
* Liquid Glass 必须可降级，不能因为视觉效果导致交互失真。

---

## 5. iOS 90 分体验目标

### 5.1 页面级目标

Beta 阶段应把四个核心页面提升到统一完成度：

* Dashboard：信息密度高，但层次清楚，不拥挤。
* Trends：图表清晰、切换顺滑、数据解释直接。
* Settings：配置项有结构，风险操作明显，状态反馈完整。
* Account：账号状态、授权状态、平台状态表达明确。

### 5.2 交互级目标

iOS 体验不是静态布局，而是“响应质量”。Beta 阶段需要强化：

* 下拉刷新反馈
* 加载态过渡
* 数据空缺时的提示
* 导出过程反馈
* Premium 锁定状态反馈
* 账号操作的确认与撤销
* 试用到期状态的表达

### 5.3 视觉细节目标

* 卡片间距统一。
* 圆角策略统一。
* 阴影与毛玻璃层级统一。
* 图表与背景关系统一。
* 文字层级统一。
* 警告、提示、成功、锁定状态统一。

这个阶段不追求多，而追求每一个元素都像是被同一套设计系统产出的。

---

## 6. 本地化与主题的交互边界

本地化和主题都属于 UI 表现层，但它们的职责不同：

* 本地化回答“文本怎么说”。
* 主题回答“界面怎么看”。

Beta 阶段必须保持这两个系统解耦。具体来说：

* 同一个文案 key 可以被多语言复用。
* 同一个主题可以在不同语言下保持一致的视觉语义。
* 不允许语言系统去决定视觉风格。
* 不允许主题系统去决定文案内容。

---

## 7. 需要新增或强化的模块

### 7.1 Localization Layer

职责：

* 管理语言枚举
* 管理本地化资源加载
* 管理用户选择的语言持久化
* 提供统一文本访问入口

### 7.2 Theme Layer

职责：

* 管理主题枚举
* 管理颜色、渐变、卡片样式、图表样式
* 管理主题切换持久化
* 管理主题视觉一致性

### 7.3 UI Polish Layer

职责：

* 调整页面布局节奏
* 统一空状态、错误状态、加载态
* 优化卡片、按钮、badge、sheet、alert 的视觉一致性
* 提升动效与层次表达

---

## 8. 当前 beta 的范围边界

Beta 不做以下事情：

* 不扩展新平台。
* 不重写数据库层。
* 不改变现有 Repository / Service 结构。
* 不引入新的数据存储引擎。
* 不以“增加功能数量”作为目标。

Beta 只做三件事：

1. 让语言真正本地化。
2. 让主题真正系统化。
3. 让 iOS 体验真正成熟化。

---

## 9. Beta 的实现顺序

推荐顺序如下：

### Phase 1：本地化基建

* 建立语言枚举
* 建立 Localizable strings 结构
* 替换主要页面的硬编码文本
* Settings 页加入语言选择

### Phase 2：主题语义统一

* 整理 Theme 协议和 ThemeToken
* 把卡片、按钮、图表、Badge 统一到主题体系
* 完成 Instagram 风格的统一视觉

### Phase 3：页面精修

* Dashboard 重排信息层级
* Trends 优化图表与说明文本
* Settings 优化结构与风险操作
* Account 优化状态徽章和授权反馈

### Phase 4：体验打磨

* 加载态、空状态、错误态统一
* 过渡动画统一
* 图表刷新、筛选切换、导出流程统一

### Phase 5：回归校验

* 多语言回归
* 主题回归
* 小屏 iPhone 回归
* 深色模式回归
* Premium 门控回归

---

## 10. Beta 的完成标准

当 Beta 版本满足以下条件时，可以认为进入下一阶段：

* English / 简体中文 / 繁体中文 / 日文都可正常展示。
* Settings 中可以切换语言并持久化。
* Apple Native 与 Instagram 主题可稳定切换。
* Liquid Glass 在可用场景下提升质感，在不可用场景下可自然降级。
* Dashboard / Trends / Settings / Account 的状态反馈清晰。
* 页面在 iPhone 机型上看起来是“完成的”，不是“临时堆叠的”。
* 现有架构没有被 UI 优化破坏。

---

## 11. Beta 的产品定义

Beta 不是“功能更多”的版本，而是“同样功能但更像一个真正的 iOS 应用”的版本。

它的关键标准不是宏观覆盖，而是微观完成度：

* 文案是否自然
* 视觉是否统一
* 反馈是否明确
* 状态是否清晰
* 交互是否稳定
* 主题是否有语义
* 多语言是否真正可用

---

## 12. Beta 版本结论

Alpha 解决的是“能跑、能存、能聚合、能展示”的问题。Beta 解决的是“这个产品是否像一个被认真设计过的 iOS 应用”的问题。

因此，Beta 的核心任务不是扩展系统边界，而是压缩 UI 与体验中的随机性，建立一套更稳定、更统一、更高完成度的表现层语义。
