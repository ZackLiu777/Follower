# SwiftUI Visual Design Principles for Codex

## 1. Visual Intent
The interface must feel native to iOS and consistent with Apple’s design language.
Avoid visual novelty for its own sake.
The screen should look calm, balanced, and immediately understandable.

## 2. Hierarchy
Use size, weight, spacing, and placement to establish clear hierarchy.
There must always be one primary focal point per screen.
Do not give equal emphasis to all content.

## 3. Spacing
Use whitespace to separate meaning, not to decorate.
Spacing must be intentional and consistent.
Do not create large empty regions unless they support focus or breathing room.

## 4. Typography
Use system fonts and system text styles by default.
Text hierarchy should follow content importance, not aesthetic preference.
Avoid arbitrary font sizes, weights, or letter spacing.

## 5. Color
Use semantic and system colors first.
Color must serve meaning, state, and readability.
Do not use color as decoration if it does not help the user.

## 6. Surfaces
Prefer simple, flat, and legible surfaces.
Use shadows, blur, gradients, and material effects only when they improve comprehension.
Do not stack multiple decorative effects on the same surface.

## 7. Icons and Images
Icons must be meaningful and consistent.
Use SF Symbols when appropriate.
Do not use icons merely to fill space.
Images must support the content, not distract from it.

## 8. Density
Optimize for useful information per screen.
Avoid oversized cards, oversized headers, and low-density layouts.
Do not convert a simple list into a dashboard unless the task truly requires it.

## 9. Consistency
Reuse the same spacing scale, radius scale, and component patterns across the product.
The same type of content should look and behave the same everywhere.
Do not introduce one-off visual treatments without product justification.

## 10. Forbidden Visual Patterns
Avoid:
- heavy glassmorphism
- decorative gradients
- oversized rounded cards everywhere
- neon or gaming-style palettes
- random drop shadows
- non-semantic color usage
- unnecessary dividers
- “AI demo” layouts with weak hierarchy

## 11. Visual Quality Standard
The final result should feel restrained, precise, and native.
It should appear designed by a product team, not generated for show.
